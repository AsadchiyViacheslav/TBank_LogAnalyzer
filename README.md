# NGINX Log Analyzer

Консольная утилита для анализа логов NGINX.
Позволяет обрабатывать один или несколько лог-файлов (локальных и удалённых), фильтровать записи по дате и формировать статистический отчёт в форматах **JSON**, **Markdown** и **AsciiDoc**.

Утилита рассчитана на потоковую обработку логов и не загружает файлы целиком в память.

---

## Возможности

Программа собирает следующую статистику:

* Общее количество запросов
* Средний размер ответа
* Максимальный размер ответа
* 95-й перцентиль размера ответа
* Частота кодов ответа
* Топ-10 наиболее часто запрашиваемых ресурсов

  * Метод запроса (`GET`, `POST` и т.д.) не учитывается
* Распределение запросов по датам (в процентах от общего числа)
* Уникальные используемые протоколы передачи данных (`HTTP/1.1`, `HTTP/2.0`, и т.д.)

Точность числовых значений: **2 знака после запятой**.

---

## Поддерживаемый формат логов

Программа обрабатывает логи NGINX в формате:

```
$remote_addr - $remote_user [$time_local] "$request" $status $body_bytes_sent "$http_referer" "$http_user_agent"
```

Пример:

```
93.180.71.3 - - [17/May/2015:08:05:32 +0000] "GET /downloads/product_1 HTTP/1.1" 304 0 "-" "Debian APT-HTTP/1.3"
```

Строки, не соответствующие формату, логируются с уровнем `WARN` и пропускаются.

## Установка

### Сборка

```bash
mvn clean package
```

После сборки в каталоге `target` появится JAR-файл:

```text
log-analyzer.jar
```

---

## Запуск

```bash
java -jar log-analyzer.jar \
  --path logs/*.log \
  --format markdown \
  --output report.md \
  --from 2025-03-01 \
  --to 2025-03-31
```

---

## Параметры командной строки

### `--path`, `-p` (обязательный)

Путь к одному или нескольким лог-файлам.

Поддерживается:

* Локальные файлы
* Шаблоны путей
* URL-ссылки на удалённые файлы

Примеры:

```
/var/log/nginx/access.log
logs/2025*
https://raw.githubusercontent.com/elastic/examples/master/Common%20Data%20Formats/nginx_logs/nginx_logs
```

Поддерживаемые расширения: `.log`, `.txt`

Ошибки:

* Файл не найден
* Формат файла не поддерживается
* Удалённый файл вернул 404

---

### `--format`, `-f` (обязательный)

Формат вывода результата:

* `json`
* `markdown`
* `adoc`

Ошибка, если передан неподдерживаемый формат.

---

### `--output`, `-o` (обязательный)

Путь к файлу, куда будет сохранён отчёт.

Требования:

* Файл не должен существовать
* Директория должна быть доступна для записи
* Расширение должно соответствовать формату:

| Формат   | Расширение |
| -------- | ---------- |
| json     | `.json`    |
| markdown | `.md`      |
| adoc     | `.ad`      |

---

### `--from`, `--to` (необязательные)

Фильтрация логов по диапазону дат.
Формат: **ISO-8601** (`YYYY-MM-DD`).

Допустимые комбинации:

| from | to | Поведение                             |
| ---- | -- | ------------------------------------- |
| ✓    | ✓  | Анализ в диапазоне [from, to]         |
| ✓    | ✗  | С даты from до последней даты в логах |
| ✗    | ✓  | С первой даты в логах до даты to      |
| ✗    | ✗  | Анализ всех логов                     |

Ошибки:

* Неверный формат даты
* `from >= to`

---

## Форматы вывода

### JSON

Выходной JSON полностью соответствует заданной схеме и содержит:

* список файлов
* общее количество запросов
* статистику размеров ответов
* топ ресурсов
* коды ответа
* распределение по датам
* уникальные протоколы

---

### Markdown / AsciiDoc

Отчёт формируется в человекочитаемом виде:

* Общая сводка
* Таблица ресурсов
* Таблица кодов ответа
* Дополнительные секции по датам и протоколам

---

## Коды завершения

| Код | Описание                                                               |
| --- | ---------------------------------------------------------------------- |
| 0   | Успешное завершение                                                    |
| 1   | Непредвиденная ошибка                                                  |
| 2   | Некорректное использование программы (параметры, пути, форматы и т.д.) |

---

## Логирование

* Все важные события логируются в `stdout`
* Используется `log4j`
* Некорректные строки логов логируются с уровнем `WARN`
* Критические ошибки приводят к завершению программы

---

## Производительность

* Логи обрабатываются потоково
* Файл не загружается целиком в память
* Подходит для больших лог-файлов

---

```bash
java -jar log-analyzer.jar \
  --path access.log \
  --format json \
  --output report.json
```
